# 2026-11-10

## 对比 `D:\script\glados-checkin-extension` 浏览器扩展与 `checkin.py`

**结论**：两者解题路线不同 —— 扩展走"浏览器内借用合法身份"，脚本走"无头环境伪造身份"。

**扩展实现要点**（MV3，5 个文件，纯前端无后端）：
- `credentials: "include"` 直接复用浏览器登录态，无需拷贝 Cookie，也就不存在 30 天过期问题。
- 用 `declarativeNetRequest` 把扩展发起的请求的 `Origin` / `Referer` 从 `chrome-extension://` 改写为站点自身 Origin。
- **关键：新增 Bot Challenge 流程** —— `GET /api/user/checkin/challenge` 拿 `nonce` → `sleep(2600)` → `proof = sha256(nonce + ".glados-observe-v1")` → `POST /api/user/checkin` 带 `{token, nonce, proof}`。
- 显式处理 `reason === "device-mismatch"` 与 `code === 4` / `automated check-in detected`。
- 调度用 `chrome.alarms` 每 15 分钟轮询，到设定时间（默认 09:00）且当日未成功才发起，失败后全天持续重试。
- 3 次重试，仅对 502/503/504 + 网络/超时重试，线性退避。
- `chrome.storage.local` 存 30 天历史，UI 展示 7 天；连续 5 次失败 → 角标 `!` + 高危横幅 + 强通知。
- 单账号，且依赖浏览器处于运行状态；无手机推送。

**探测到的现状（重要）**：
- `/api/user/checkin/challenge` 在 `www.glados.vip` 与 `glados.one` 上**都已存在**（返回 200 JSON），说明风控已升级到需要挑战应答。
- 9 月那次使用的 Cookie 已失效：`/api/user/status` 返回 `{"code":-2,"message":"没有权限"}`，因此无法实测纯 token 流程是否仍可用。
- **推断：`checkin.py` 目前很可能已再次失效**，因为它没有 nonce/proof 逻辑。
- `glados.one` 与 `www.glados.vip` 均直连 Cloudflare 后端，无跳转，属多域名并行。
- 扩展里 `API_BASE = glados.one` 但 `CHECKIN_TOKEN = "glados.cloud"`，域名与 token 不一致，按 9 月的规则本该失败 —— 存疑点，可能是服务端改为以 nonce/proof 为主、token 仅作兼容。

**尚未做的**：未把 challenge/proof 流程移植进 `checkin.py`（用户只要求对比，已提出可代办）。

## 下午：已把 Bot Challenge 移植进 checkin.py（v1.3.0）

用户提供了新版 Cookie（只有 `gld:sess` + `gld:sess.sig`，没有 `koa:sess`），**单独就够用**。

**实测结论（修正了上午的推断）**：
- 纯 token `{"token":"www.glados.vip"}` 仍然返回 `code:1` + `"repeated":true`，**没有被 device-mismatch 拦**。
  所以服务端对挑战的强制程度存疑，可能只在真正首次签到时校验。
- challenge 接口正常：`{code:0, nonce:"...", ttl:300000}`（5 分钟有效）。
- 带 `{token, nonce, proof}` 提交同样返回 `code:1`，证明公式无误。
- 今日 `streak:0`、`today_gain:1`（积分经济从 9 月的每日 5 分变成 1 分）。

**实现**：
- 常量 `CHECKIN_PATH` / `CHALLENGE_PATH` / `CHALLENGE_SALT='glados-observe-v1'` / `CHALLENGE_WAIT=2.6` / `TIMEOUT=(6,20)`。
- `solve_challenge(domain)` 三态返回：dict=拿到 nonce、None=接口可用但无 nonce（回退纯 token）、False=域名不可达。
- `checkin()` 每个域名独立走「领挑战 → 提交」全链路，避免 nonce 与域名错配。
- `req(..., domains=[...])` 支持限定域名；默认优先复用 `self.domain`（上次成功的域名），避免反复踩超时域名。
- `is_success` 新增识别 `reason='device-mismatch'`、`没有权限`、`automated check-in detected`。
- 记录 `self.mode`（challenge/plain）与 `self.repeated`，日志和推送都会标注「今日已签」。
- 删掉了不再使用的 `data_fn` 参数。

**验证**：编译通过；完整跑通输出 `✅ 积分: 338 | 天数: 314 | 今日+1 | 挑战应答 | 今日已签`。
推送 HTML 用假 `pushplus` 拦截验证，渲染正确。
