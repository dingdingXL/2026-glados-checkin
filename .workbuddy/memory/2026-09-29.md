# 2026-09-29

## 修复 GLaDOS 签到失效（v1.2.0）

**现象**：GitHub Actions 跑完显示"成功0/1"，签到接口返回 `Today's observation logged. Return tomorrow for more points.`（其实这是**成功**文案，被脚本误判为失败）。

**根因**：官网迁移到 `www.glados.vip`，签到接口会核对 token 与请求域名是否一致（含 `www.` 前缀）。脚本写死的 `glados.cloud` 不再匹配 → 返回 "please checkin via ..."。

**改动 `checkin.py`**：
1. `DOMAINS` 首位改为 `https://www.glados.vip`，其余保留作回退。
2. `req()` 新增 `data_fn` 参数（按当前域名动态构造 body），并记录 `last_err` 便于排查。
3. 新增 `token_of(domain)`：token 由实际命中的域名生成，不再写死。
4. 新增 `is_success(res)`：**只按 message 文案判断**，因为签到成功 `code=1`、`/api/user/status` 成功 `code=0`，各接口 code 语义不一致。
5. `get_status()` 记录 `system_date`；`get_points()` 若 `history[0].detail == 今天` 则取 `today_gain`。
6. 推送新增「今日获得积分」「连续签到天数」；签到响应里的 `points` 字段**恒为 0**，不能用。
7. UA 更新为 Edge 149，补齐 `sec-ch-ua*` / `sec-fetch-*` / `priority` / `accept-language`。
8. 顺手修掉 `extract_cookie()` JSON 分支的 `koa.sess=` 拼写错误。

**实测**：2026-09-29 用真实 Cookie 跑通，输出 `✅ 积分: 38 | 天数: 356 | 今日+5`。
Telegram HTML 转换也用假 post 拦截验证过，格式正常。
